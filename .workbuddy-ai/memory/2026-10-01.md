给出的核心建议（结论）：
- 混淆根因不是记忆力，是"并行学 + 只背语法不建模型"。原则：串行不并行、深度优先、只求"能读能改"。
- 推荐起步顺序：Dart 或 Python → Kotlin → Swift（Swift 放最后：需 Mac，且 struct 值语义离前端最远）。
- 知识分四层：语法关键字（查手册）/ 惯用法（读代码）/ 类型系统（必懂）/ 并发与内存模型（必懂）。
- 学新语言只问四个问题：类型系统、并发模型、错误处理、值语义 vs 引用语义。
- TS 是结构化类型 + 编译期擦除，会误导对 Kotlin/Swift/Dart 名义类型系统的直觉 —— 需主动"忘掉"。
- 方法：翻译法（JS 代码逐行翻译）+ 同一项目四语言重写 + Anki 只记差异点 + 背惯用法不背语法。
- 资源重点：Exercism（同题多语言）、hyperpolyglot.org（语法并排对照）、Kotlin Koans、Fluent Python、The Swift Programming Language（官方免费）。

**本次实现踩到的硬坑（都已固化进 skill `vue3-static-content-site-ssg`）：**
1. `npm install` 中断留下 `.package-lock.json` 错状态 → @esbuild/@rollup 平台包永远不装，重装也说 "up to date"。要显式补装或用 `--ignore-scripts` 重装
2. **Git Bash 会改写以 `/` 开头的环境变量**（`PC_BASE_PATH=/` → MSYS 根目录的绝对路径），导致 vite base 非法、构建失败。改用 `PC_BASE_PATH=repo-name`（不带斜杠）
3. 块注释里写 `content/languages/*/meta.yaml` 的 `*/` 会提前闭合注释 → 报一个完全指不到病灶的语法错误
4. YAML 普通标量：以 `` ` ``/`*`/`@` 开头非法；含 `": "` 也非法；**批量加引号脚本会误伤 `body: |` 块标量**（一次毁 67 处），还会误改块标量内部的 `x: int = 1` 这类代码行
5. `vite-ssg` 的 `dirStyle` 默认 `flat` → GH Pages 上只有首页能打开，必须显式 `nested`
6. Shiki 默认 bundle 不含 `css-variables` 主题，必须 `createCssVariablesTheme()`；且该主题不输出 font-style/font-weight（Q5 实测结论），已在 CSS 侧按 token 变量名补偿
7. VueUse `useLocalStorage` 的编码**按默认值类型**决定（string 原样、array JSON）→ 值写坏时界面"一个选项都不高亮"且不报错。已加 `allowed` 守卫
8. jsdiff `diffLines` 会把差异块合并，导致相同行也被标"不同"→ 改用 `diffArrays` 逐行精确对齐

心智模型对照从 12 组补到 26 组。

**本阶段最重要的两个发现（都是"实测推翻设计假设"）：**

1. **分片粒度错了**：架构文档原本定「按 topic 分片」，在 8 个 Feature 时看不出问题；
   补到 72 个 Feature 后单 topic 分片达 **732 KB**，首屏要下载整章 8 倍数据。
   这正是文档 §9.1 里预先写好的触发条件（「单章分片超预算就按 section 细分片」）——**触发并修正为按章分片**。
   改后单章 69–107 KB，gzip 后仅 8–11 KB。
   顺带实测到 gzip 对 Shiki 高亮 HTML 的压缩率约 **9:1**（709 KB → 77 KB），
   所以 7 语言时仍有 5 倍余量，不需要激进再拆。

2. **一个真实的健壮性缺陷**：`verify:ext` 会在**真实内容目录**里造临时语言来验证「加语言只加数据」，
   进程一旦被中断就留下残留，导致整个仓库的 validate 与测试失败——
   表现为**测试间歇性失败**，报一个与真实内容毫无关系的 R8 错误。
   根因是手工造残留目录复现出来的（而不是猜的）。
   修法：确立**私有目录约定**（`_` 前缀默认不进构建与校验），fixture 改成 `_fixturelang`，残留变成无害。

   连带补上一个 design-to-code 缺口：文档里写了 `content/languages/_template/` 作为新增语言脚手架，
   但 loader 根本没跳过下划线目录——真去复制它反而会把构建搞崩。现在 `_template/` 已可用。

**其它改动**：
- 实现文件从「每语言一个大 snippets.yaml」拆成「一章一文件」（`snippets/<NN>-*.yaml`），loader 两者都支持并合并
- `verify:ext` 增加一条断言：私有目录必须在正常构建中不可见
- 修掉一处文案瑕疵：章节页把发布策略名 `include-draft-with-badge` 直接渲染给了读者

**当前验证状态**：typecheck 0 error · 23 测试通过 · verify:ext 通过 · 87 条路由预渲染且逐页内容验收通过。
