# 对比列语言 · 术语与适用性

> 这份文档服务于 **S11**（新增 7 门对比列语言，见[台账](项目步骤规划与进度台账.md) §6.7）。
> 它回答三个动笔之后会反复要查的问题：
> ① 这门语言管这个东西叫什么？② 这个知识点在这门语言里到底有没有？③ 样张暴露了哪些结构问题？
>
> **它不是规则** —— 规则在[内容书写标准.md](内容书写标准.md) §5.1。这里只放事实与判断。
> §2 的矩阵是**预判**，不是结论：真正写那一组时要按内容实际形态修正它。

## 1. 术语表

每门语言用它自己官方文档里的叫法，全站统一。**写作时先查这里，不要临时换词** ——
同一门语言在 104 个格子里用同一个词，读者才建立得起映射。

| 概念 | TypeScript | ArkTS | Kotlin | Swift | Dart | C++ | PHP |
| --- | --- | --- | --- | --- | --- | --- | --- |

| 不可变绑定 | `const` | `const` | `val` | `let` | `final` | `const` | `const`（仅编译期常量） |

> 而 TypeScript 的 `as` 恰好是「不做运行时检查」的那个 —— 同一个关键字在两边安全性相反。
> **PHP 的 `const` 只是编译期常量**，不是「不可重新赋值的变量」，没有对应概念时用 `readonly`（8.1+）或干脆讲没有。

> **轮 ② 实测修正（2026-10-03，Kotlin 与 Dart 已写完）**：矩阵大体站得住，
> 只有一处记号要调 —— **Kotlin 与 Dart 的 `memory` 都从 ○ 降到 △**：
> 两门都有一半的格是 `absent`（`ownership-borrow` 与 `lifetime` 对两者都不成立），
> 真正有话可说的只有值/引用、GC 与弱引用三格。
> 另一处是 **`concurrency` 对 Dart 的 ● 要加个注**：内容确实充足，
> 但充足的原因是「**没有**什么可说」—— `lock-mutex` 与 `atomicity` 两格都是 `absent`，
> 用整整两格来说明「语言把问题从根上去掉了」。这不是内容单薄，是这一组的答案本就这样。
> 其余各格与预判一致，`generics` 对 Dart 的 ● 尤其准确（协变 + 具体化两个轴都与 Java 相反）。

**几处值得先记下来的**：

- **`generics` 对 PHP 是 `∅`** —— PHP 没有泛型，只有文档注解（`@template`）。这一格会是纯粹的 `absent` + 「那你们怎么办」的说明。
- **`memory` 对 TS / ArkTS 是 `∅`** —— 有 GC 但语言层不暴露，写不出与基准的实质差异。而 C++ 与 Swift 在这一组是 ●（手动管理 / ARC），是它们最有价值的格子。
- **`concurrency` 对 PHP 是 `∅`** —— 共享无状态的请求模型，一次请求一个进程，没有语言级并发原语。
- **`meta` 对 ArkTS 可能是 ●** —— 装饰器（`@State` / `@Prop` / `@Link`）是它写 UI 的核心手段，比在 TypeScript 里更中心。
- **C++ 的 ● 密度最高**，且集中在 `model` 与 `mechanism` 两组 —— 它离三个基准都远，可写的东西最多，也最贵。

## 3. 样张暴露的问题

### 3.1 `equivalence` 的口径必须成文（已在 §5.1 补）

写样张时，同一个知识点在不同语言下出现了分歧判断：**`structural-nominal` 这一格，
Kotlin 对 Java 记 `analogous`（两者都是名义类型），而 Go 对 Java 记 `divergent`**。
两者都对 —— 判的是「各自与 Java 的关系」，不是语言的绝对属性。
但边界不写清楚，跨批次就会出现同一格判断不一致。判据已补进 §5.1 第 6 条。

### 3.2 ArkTS 与 TypeScript 的同质化（陪跑样张的结论）

`express/bindings` 陪跑样张的结果：**6 格里有 5 格对 TypeScript 侧的判断是
`identical` 或 `analogous`，真正有差异的是 `hoisting`**（ArkTS 的静态检查直接
否掉了依赖提升的写法）。其余几格的 `vs` 只能落在「ArkTS 的检查更严」这一句上。

这印证了按对比轴配对（轮 ① 把 TS 与 ArkTS 放一起）而非按谱系分的判断：
ArkTS 的价值集中在少数几组（`practice/*`、`mechanism/concurrency`、
`mechanism/meta`、`model/modules`），**其余组应当如实标 `identical` + 一句短说明，
不要为了填满而灌水**。矩阵里 ArkTS 的 △ 就是这些格子。

### 3.3 知识点切分：`types` 组目前不必动

主样张 `mechanism/types` 的 6 格在 7 门语言里都成立，没有出现
「两格在每门语言里说的都是同一句话」的过切分信号。
`static-vs-dynamic` 与 `type-annotation` 相邻但不重复（前者问「什么时候查」，
后者问「怎么写」），`type-narrowing` 与 `type-assertion` 也分得开。
**结论：池不动。**

### 3.4 一处写作纪律（已补进 §5.1 第 3 条）

样张写作中真的踩到了 R25：在 `vs.python` / `vs.java` 里为了做三方对比
把 JavaScript 拉了进来。**一份 `vs` 只许出现两门语言**，这一条在写「A 与 B 差在哪」
时特别容易破 —— 因为解释差异时天然想引第三个参照物。

## 4. 工时账

样张实测（可作为全量的换算基准）：

| 项 | 量 |
| --- | --- |
| 单格 YAML 平均行数 | 约 35–40 行（`code` 8–15 行 + 三份 `vs` 各 4–6 行 + `equivalence`） |
| 样张总量 | 12 格 × 7 门 = 84 格，约 2200 行 |
| 全量换算 | 728 格 ≈ **2.6–2.9 万行 YAML**，是样张的 13.5 倍 |

按每轮 44 个文件（2 门 × 22 组）计，**轮 ① 的粗略体量与现存 5 门语言之一相当**。
真正决定节奏的是 `●` 密度：C++（轮 ③）与 PHP（轮 ④）的格子写法最重，
但 PHP 有大量 `∅`（`generics` / `concurrency` / 部分 `memory`），实际不一定更慢。

### 5.1 ArkTS：八条会成为高频判据的事实

| 事实 | 出处 |
| --- | --- |
| `as` **不做**运行时检查、不转换值；断言错了**静默不生效**（不抛异常） | 官方 FAQ |
| 但**编译期管得死**：毫无继承关系的类型之间不许断言；且禁 `any`/`unknown`，`x as unknown as T` **写不出来** | `arkts-no-any-unknown` + 迁移指南 ArkTS 侧示例 |
| **默认严格空安全**，`?.` / `??` 可用 | 语言导览 |
| `let x;`（无初值也无标注）是**编译错误** | 语言导览 |
| **构造函数支持重载签名**（多个签名头 + 一个实现体） | 语言导览「Constructor overload signature」 |
| `Record<K,V>` 是官方给的动态键形态，索引读出的类型**含 `undefined`**；`Object.fromEntries` 反而被禁 | `arkts-no-utility-types` / `arkts-limited-stdlib` |
| 函数**参数**类型必须有；**返回类型可推断但受限**；**回调参数类型由上下文推断、可以省** | `arkts-no-implicit-return-types` + official more-cases 示例 |
| 只能抛 `Error` 及其子类 —— 是**硬性编译规则**不是惯例 | `arkts-limited-throw` |

另外这批内容用到的禁用项（都已核到规则名）：函数表达式、生成器、解构（声明/赋值/参数
三条）、`for...in`、`var`、`Symbol`（仅 `Symbol.iterator` 可用）、展开（只许传给剩余参数
与复制数组）、`Object.fromEntries` / `Object.assign` / 原型改写、`as const`、
`let v!: T`（这条是 **warning** 级，不是 error）。

### 5.2 写反过的（同类错误最值得警惕）

- **ArkTS 的 `as`**：一度写成「会做运行时检查」，与事实正相反（见 5.1 第一条）。
- **`slice` 的负下标**：写成「`slice` 不支持、只有 `at()` 认」—— 实际 `slice` 与 `at` 都认，
  不认的是 `substring`。
- **函数表达式**：当作 ArkTS 的合法写法列进「三种写法」，实际 `function (x) {}` 是编译错误。
- **构造函数**：写成「没有重载」，实际有重载签名。
- **动态键**：写「只能改用 `Map`，中间那条路被堵死」，漏了 `Record`。
- **`throw`**：写成「抛 `Error` 是惯例」，实际是编译期硬规则。
- **迭代协议**：把「解构、展开都认 `Symbol.iterator`」一并写了，实际两者在 ArkTS 都不支持。
- **`let z;`**（TS 侧）：写成「检查从这里断掉」，实际是 evolving any —— 赋值前访问会被拦下，
  赋值后按所赋的类型检查。
- **`??`** 的编译检查（TS 侧）：写成「左边类型不含 null 就提醒」，实际**只看语法**。
- **未处理的 promise 拒绝**（TS 侧）：写成「只是警告，程序不会停」——
  **Node 自 v15 起默认终止进程**，而 TS 的主力服务端运行时正是 Node。

### 5.3 证据不足、已删掉的断言

凡是官方文档里找不到依据的，一律删掉而不是留着 —— 这一批删了五处：
ArkTS 的**穷尽性检查**（`never` / `assertNever` 那套）、`catch { }` **省略绑定**、
`import './polyfill'` **纯副作用导入**、**函数声明提升**的具体行为、
以及「老项目里 `?.` 更多」这类**风格年龄相关性**判断。

### 5.4 轮 ① 第 3 批（`mechanism`）的调研结论

**最重要的发现：ArkTS 有两份互相矛盾的文档，只许引用其中一份。**

| 文档 | 描述的语言 | 与仓库的关系 |
| --- | --- | --- |
| **app 开发文档**（`quick-start/`、`arkts-utils/`） | API 12 / HarmonyOS NEXT 的 `.ets`：**actor 模型、内存隔离** | ✅ **仓库的目标版本，只引它** |
| **ArkTS 静态语言规范 1.2**（`arkcompiler_runtime_core/…/ets/doc/`） | 技术预览：有 `int` / `tuple` / **共享内存** / 声明处型变 `in`·`out` | ❌ 与上一行**直接冲突** |

冲突实例：app 文档说运行时是「actor model with memory isolation」，静态规范说
「program memory is shared between all C_JOBS」。按后者写，写出来的东西**不属于目标版本**。

| 主题 | 只引 app 文档时能写的事实 | **无官方依据 → 不写** |
| --- | --- | --- |
| `concurrency` | actor 模型 + 内存隔离；TaskPool / Worker 两套；跨线程三条路（Structured Clone 深拷贝 / ArrayBuffer·Transferable / **`@Sendable` 在共享堆按引用传递**）；**只有异步锁** `AsyncLock`（非阻塞，必须 `await`），另有 `ConditionVariable`；`SharedArrayBuffer` + `Atomics`；数据竞争是**开发者责任**，编译器不管 | 内存序（memory order）；「编译器会检测数据竞争」 |
| `async` | Promise / async-await；microtask 事件循环；未处理拒绝有 `globalUnhandledRejectionDetected` 全局事件；**TaskPool 的任务可取消，Worker 不可**（只能销毁线程） | **`AbortController` / `AbortSignal`**（DOM 式）；`setTimeout` 与 Web 的语义一致性 |
| `generics` | `extends` 约束、默认类型实参；禁条件类型（含 `infer`）/映射类型/交叉类型/索引访问/索引签名/类型查询/`this` 类型；工具类型只留 `Partial`·`Required`·`Readonly`·`Record`；**推断受限**（不能只靠返回类型推断出 `T`） | **型变**、**类型擦除** —— app 文档零覆盖 |
| `memory` | number / string 是基本类型（值语义），object / array / function 是引用类型；**没有用户自定义 struct**（`struct` 是 ArkUI 组件语法）；**tracing GC，明确不用引用计数**（理由是会漏循环引用），分代 young/old、有阈值与堆上限 | **`WeakRef` / `WeakMap` / `WeakSet` / `FinalizationRegistry`** —— 既不在禁用名单里，也没有文档保证可用 |
| `meta` | **反射的入口基本被关掉**：`eval`、`Object.getPrototypeOf`、`Proxy` 的 **13 个 trap 全禁**、`Symbol`（只留 `Symbol.iterator`）、`globalThis`（**警告**级）、`delete` 运算符、`in` 运算符；官方承认的替代是 **dynamic import**（原话是「达到类似 `Class.forName()` 的效果」）；ArkUI 的 `@State` / `@Prop` / `@Link` 等属 **ArkUI 框架**，语言层只有 `@Sendable` / `@Concurrent` | 运行时拿类型信息；`Proxy` 的官方替代品 |

> **两格要特别处理**：`variance` 与 `type-erasure` 在 ArkTS 侧**没有官方依据**。
> 它们**不标 `absent`**（ArkTS 有泛型，不是「本语言没这个概念」），而是如实写明
> 「官方文档没有定义这件事」—— 对读者来说，「这门语言不提供这个工具」本身就是有用的事实。

### 5.5 一条流程纪律

核实里有一半以上的错误属于**「想当然」**：把 TypeScript 的行为套到 ArkTS 上、
把 JavaScript 的细节记混（`slice` 负下标）、把「惯例」当「规则」。
**写「另一门语言怎么做」时，落笔前先查官方文档** —— 这类断言错得越自然，
读者越不会怀疑。TS 侧的 `code` 块尤其要**真的编译一遍**：
被标成正面示例的行如果根本编译不过，比写错一句话更伤读者。

### 5.6 轮 ① 第 3 批后半（`generics` / `memory` / `meta`）的调研结论

这一轮把范围扩到了**三个基准侧**：每份 `vs` 里「对手语言怎么做」同样是断言，
写错了和写错本语言一样伤读者。结论见下（最后两条不是事实，是这一轮促成的规则改动与方法）。

#### 一、推翻前文的三条（§5.4 表格已就地改正）

| 原文 | 事实 |
| --- | --- |
| 「`Reflect` 全禁」 | **只有 9 个方法**在禁用清单里（含 `getPrototypeOf` / `setPrototypeOf` / `defineProperty` / `deleteProperty`）。全禁的是 **`Proxy` 的 13 个 trap** —— 那 13 个凑齐就等于 `Proxy` 不可用，但 `Reflect` 不能这么写 |
| 规则名 `arkts-no-indexed-access` | **没有这条规则**。索引访问类型是 `arkts-no-aliases-by-index`，按索引取字段是 `arkts-no-props-by-index` |
| 「`globalThis` 被禁」 | 属实，但级别是**警告**不是错误 |

#### 二、一条全新发现：**注解与装饰器是两套机制**

§5.4 只记了「反射基本被禁」，漏掉了 ArkTS **自己的**一套注解（官方语言指南「关键字」一节）：

| 事实 | 出处 |
| --- | --- |
| `@interface` 声明注解，**不是**那门语法相近的方言的特性，**只能在 `.ets` / `.d.ets` 里用** | 语言指南原文 |
| 自 **API 20** 起支持用户自定义注解；自 **API 24** 起支持自定义**源码态**注解 | 同上 |
| `@Retention({policy: RetentionPolicy.SOURCE})`，`Retention` / `RetentionPolicy` 从 `@kit.ArkTS` 导入 | 同上 |
| 当前只能标在**类声明与方法声明**上；字段限于 `number` / `boolean` / `string` / 枚举及它们的数组；注解必须定义在**顶层作用域** | 同上 |
| 语言指南**只描述了源码态的保留策略**：生命周期只在编译期、不影响编译产物 | 同上 |

> ⚠️ **社区与第三方资料里流传的 `Class.getAnnotation()` / `Element.getAnnotation()` /
> `RetentionPolicy.RUNTIME`，在官方语言指南里查不到**（两次独立抓取都没有）。
> 第 3 批内容因此只写「官方给出的保留策略是编译期的、没有给出运行期读取的接口」，
> **不写**运行期反射注解——这正是 §5.4 那条纪律的又一次应用。
>
> 另一侧是明确的：官方适配规则文档开篇写「ArkTS 支持自定义装饰器，语法与 TS 一致」。
> **装饰器与注解是两个词指两件事**：装饰器本身就是行为，注解是元数据。

#### 三、这两组里「有官方依据」与「没有官方依据」的分界

| 主题 | 能写的事实 | **无官方依据 → 不写** |
| --- | --- | --- |
| `generics` | 函数 / 类 / 接口都能泛型；`extends` 约束；类型参数有默认值；**推断受限**（`arkts-no-inferred-generic-params`：不能只靠返回类型推出类型实参）；禁用项可列全（条件类型含 `infer`、映射类型、交叉类型、索引签名、索引访问类型、类型查询、`this` 类型），工具类型只留 `Partial` / `Required` / `Readonly` / `Record` | **型变**、**类型擦除** —— app 文档零覆盖；`x instanceof T`（T 为类型形参）也没有任何官方说法 |
| `memory` | 官方措辞是**「基本数据类型」与「引用类型」**（**没有**用「值类型」这个词）；`number` / `string` 属基本数据类型；`struct` 只在 ArkUI 自定义组件里用、**不是类型**；**tracing GC，明确不用引用计数**，理由原文就是「引用计数会因循环引用而漏」；分代（年轻代 / 老年代）；堆有默认上限（主线程与 worker 各一档） | `WeakRef` / `WeakMap` / `WeakSet` / `FinalizationRegistry` —— **既不在禁用清单里，也没有可用说明**，只能写「文档没有把它列为可用能力」 |

> `variance` 与 `type-erasure` 两格按 §5.4 的决定处理：**不标 `absent`**
> （ArkTS 有泛型，说「本语言无此概念」是错的），如实写「官方没有定义这件事」。
> 这个区分值得再说一遍：Go 的 `variance` 标 `absent` 是因为它**明确规定**了泛型实例之间
> 没有子类型关系 —— 那是「官方定义了没有」，与「官方没定义」不是同一件事。

#### 四、基准侧的四处更正（**这一轮最容易被忽略的收获**）

| 原本会写成 | 事实 |
| --- | --- |
| 装饰器「在 TC39 已经是 stage 3 很久了」 | **已被降回 2.7 阶段**，从未进入任何 ECMAScript 版本；实现方仍只有 TypeScript 与 Babel |
| 「Java 18 起终结器默认禁用」 | **JEP 421 只是加了可选的关闭开关**，原文写「Finalization remains enabled by default in JDK 18」；至今仍默认启用 |
| Python「取不回类型实参」 | `list[int].__args__` 运行期**真的**返回 `(int,)`。成立的是「运行期不做类型检查」（`isinstance(x, list[int])` 会抛 TypeError） |
| 「`(a: Animal) => void` 不能赋给 `(d: Dog) => void`」 | **方向反了**。`strict` 下不可赋值的是 `(d: Dog) => void` → `(a: Animal) => void`（函数参数**逆变**）；方法参数仍是双变的，`Array<T>` 因此保持协变 |

另有两处措辞层面的：Java 的 `System.gc()` 官方用词是 **suggests**（不是「hint」）；
Python 的官方 FAQ 只说 **"passed by assignment"**，并没有出现「按值传递」或
「传对象引用」的说法 —— 后两个是社区叫法，不能归给那份 FAQ。

#### 五、这一轮促成的规则改动：R25 的「同族豁免」（ADR-71）

这一批的受控试启把 **TypeScript** 翻成启用后，**既有五门语言的内容**立刻报出
**53 处 R25**，全是「JavaScript 里没有泛型，只能上 TypeScript」这一类句子。
它们不是写错的，是**规则按逐字点名判**的必然结果 —— 那些文件写的时候，
TypeScript 还不是一门语言。

处理方式是给 R25 加一条**同族豁免**：`registry.yaml` 的 `mentionGroups` 里同组的语言
互相点名不算幽灵。判据按**两门**算（本语言或该格面对的基准同族）—— 只看本语言只能
消掉一半，Python / Java / Go / Rust 的 `vs.javascript` 格仍会报。实测：改完之后
同一次试启里 R25 从 19 条聚合行降到 **0**。

**ArkTS 刻意不在这个组里**：它不是 JavaScript 的超集，是一门独立的语言，
讲 JavaScript 时提到它确实是屏幕外的另一门。这一条同样适用于本站的写作纪律 ——
**ArkTS 的内容里不要出现 TypeScript 的名字**（用「语法相近的那门静态方言」这类泛指），
反过来 TypeScript 的内容里则可以正常提 JavaScript。

#### 六、方法上的一条补充：**「声称会报错」的行也要验**

TS 侧的代码块逐个抽出来用仓库自带的 5.9.3 以 `--strict` 单独编译
（**必须一块一个文件** —— 不同格会声明同名类，合起来编会撞名，撞出来的错误会掩盖真问题）。
这一轮除了验证正面示例能过，还把**注释掉的「编译错误」行单独拿出来编一遍**，
确认错误码与说法对得上（`TS2345` 约束不满足 / `TS2693` 类型参数当值用 /
`TS2322` 函数参数方向 / `TS2588` 给常量赋值）。运行时的断言同样实跑：
协变数组写入后调用不存在的方法确实是 `TypeError`。

反面例子写错比正面例子更容易蒙混过关 —— 读者不会去编译一段「据说是错的」代码。

## 6. 轮 ②（Kotlin + Dart）的核实记录（2026-10-03）

方法与轮 ① 相同（见 §5.5），但**这一轮有一处条件变了，收获也随之变了**：
**本机装了 Dart SDK**（Flutter 3.19.6 自带 3.3.4），所以 Dart 侧能**边写边实跑**；
Kotlin 侧没有编译器，仍然只能查官方文档。两种条件的产出对比很清楚：

| | Kotlin（读文档） | Dart（实跑） |
| --- | --- | --- |
| 抓到的错误类型 | **写反、写反、再写反**（方向性错误） | **写反 + 写过时**（数值与行为） |
| 典型例子 | `shadowing` 对 Java 的判断整个反了；「默认值只算一次」说反 | `1 == 1.0` 实为 true；`switch` 不需要 break |
| 能不能自己发现 | 不能 —— 读文档读到的是自己预期的答案 | **能** —— 跑出来的数字不听辩解 |

**结论：能实跑的语言一定实跑。** 读文档最容易放过的是「我以为我知道」，
而实跑对这类错误零容忍。轮 ③ 的 Swift 与 C++ 如果本机有工具链，照此办理。

### 6.1 我自己写反的两处（都在 Dart 侧，实跑抓出）

- **`1 == 1.0` 在 Dart 里是 `true`**，我写成 `false`，并且在 `vs.python` 与 `vs.java`
  里各据此外推了一句结论 —— **一个根断言错了，三处一起错**。
  顺带确认 **Kotlin 那边是 `false`**：同一件事两个语言相反，已按各自实测分别写。
- **`switch` 的非空分支不需要 `break`**，也不贯穿；只有**空的** case 会落下。
  我按 C/Java 的印象写成「不写 break 编译期就报错」，`dart analyze` 干净通过直接推翻。
  这条一改，与 Java 的对比方向整个反了：不是「Dart 用编译器堵住坑」，
  而是「两边对 `break` 的期待正好相反」。

### 6.2 Kotlin：会成为高频判据的硬事实

按「与三个基准差在哪」组织，写 Kotlin 时先查这张表：

1. **`==` 是结构相等（调 `equals`）、`===` 才是引用相等** —— 与 Java **恰好相反**。
   同一个符号在两个语言里含义相反，是迁移时最容易做出错误判断的一处。
   配套细节：`Double` 按 IEEE 走（`NaN != NaN`）；可空数值会装箱，
   JVM 只缓存 -128..127，所以 `100` 的 `===` 为 true、`1000` 为 false —— **别依赖它**。
2. **没有隐式数值拓宽**（`val l: Long = intValue` 编译不过），
   **但混合运算允许**（结果取宽的那个）—— 这处看起来矛盾，是从 Java 过来的第一堵墙。
3. **块体函数的返回类型不能省**（`Unit` 除外）；表达式体才能推断。
4. **`val` 只锁引用**；只读集合 `List` ≠ 不可变（是视图），
   而且**只读集合协变、可变集合不变** —— 这正是「为什么必须拆成两个接口」的答案。
5. **类与成员默认 final** —— 也是 Mockito 在 Kotlin 上失效的根因。
6. **没有 `static`**（用 `object` / `companion object` / 顶层函数替代）、**没有 `new`**。
7. **没有受检异常** —— 签名里没有 `throws`。反向的坑同样要写：
   Kotlin 的异常给 Java 用时**默认不在 throws 列表里**，要标 `@Throws`。
8. **没有 C 式 `for(;;)`、没有三元运算符、`when` 没有贯穿**；
   开区间现在写 `..<`（`until` 已不再被 ranges 页文档化）。
9. **`vararg nums: Int` 在函数体内是 `IntArray`**，引用类型才是 `Array<out T>`。
10. **`@Retention` 默认就运行期可见**（官方原话是「两者都为真」）——
    **比 Java 的默认（`CLASS`）更开放**，从 Java 搬过来的注解会更「可见」。
11. **命名**：全大写的判据是「`const val`，或顶层/单例中持不可变数据的 `val`」，
    **不是「val 还是 var」**；包名全小写且**不用下划线**。
12. **顶层变量首次使用时才初始化**；在初始化前读到什么属于**未定义行为**
    （JVM 上恰好是 0/null），不能当语言保证写。
13. **反射要额外加一个依赖**（`kotlin-reflect`），不加就是运行期缺类；
    `KClass` 与 Java 的 `Class` 要显式互转。

### 6.3 Dart：会成为高频判据的硬事实

1. **`/` 永远给小数、整除写 `~/`**；**`%` 的结果永远非负**（`-7 % 3` = **2**，
   `remainder()` 才是 -1）—— 后者与另外两个基准都相反，且**一行代码给出不同的数**。
2. **`1 == 1.0` 为 true**（数值相等即相等），但 `identical(1, 1.0)` 为 false。
3. **Dart 的 `const` 不是 JavaScript 的 `const`** —— 它要求编译期常量且**深度冻结**；
   「只锁绑定」那一档在 Dart 里叫 **`final`**。三个关键字在两边对不上号。
4. **`switch` 非空分支不需要 `break`、也不贯穿**；只有空 case 会落下。
5. **泛型两轴都与 Java 相反**：Java 是**不变 + 擦除**，Dart 是**协变 + 具体化**
   （`x is List<int>` 能跑）。协变的代价：`List<num> xs = <int>[1]; xs.add(1.5);`
   编译通过、运行期抛 `TypeError` —— 更像 Java 的**数组协变**。
   另外 Dart **没有下界**（没有 `? super T`）。
6. **isolate 内存隔离 → 没有锁、没有原子类型**。这不是「还没提供」，
   是共享内存被拿掉后它们失去对象；`lock-mutex` 与 `atomicity` 两格写 `absent`。
   代价是通信要拷贝（不可变对象会被共享，其余传递式拷贝）。
7. **`Future` 不能取消** —— `dart:async` 里根本没有 cancel。
   能真取消的只有 `StreamSubscription.cancel()`；
   另一个包里的 `CancelableOperation` 取消的也只是「结果的交付」。
8. **`Future.wait` 默认等全部完成才报第一个错误**（实测：慢任务 80ms、报错在 87ms），
   要「一出错就返回」得显式 `eagerError: true`。
9. **`Stream` 默认是单订阅的**（只能消费一次），不是广播。
10. **迭代器是 `moveNext()` + `current`** 两个动作，不是 `hasNext` / `next` 那一对。
11. **没有可变参数、没有参数化测试** —— 两项都是三个基准都有而它没有的，
    要写清替代方案，不能只说「没有」。
12. **`_` 是库级私有**（同库的其它类能访问）；而且**私有成员在同库内属于隐式接口**
    （同库 `implements` 必须实现它），跨库才不必。
13. **`pubspec.lock` 按包的类型分**：应用**建议提交**、库包**不要提交** ——
    与「锁文件一律入库」的直觉相反。
14. **没有官方 REPL**（本机实跑确认：`dart` 不带参数只打印用法就退出）。
15. **`dart:mirrors` 只在 Native 的 JIT 上**（Experimental，Flutter / AOT / web 都没有）——
    这条解释了它为什么靠 `build_runner` 做编译期代码生成。
16. **断言默认关**（要 `--enable-asserts`），与「断言默认开」相反。
17. **`dart format` 是可配的**（`page_width` / `trailing_commas` / 逐文件标记注释）——
    **「完全不可配置」是旧说法**；另要提醒 **3.7 起换了排版风格**，旧代码格式化后 diff 很大。

### 6.4 一条架构边界：`@note` 装不进别家注释语法的代码块

`pubspec.yaml` 用 `#` 注释、shell 命令也用 `#`，而 `@note` 的解析要求标记出现在
**该语言自己的注释前缀**（Dart 是 `//`）之后。于是这些块里的 `@note` 全部残留，
`content:validate` 报了 **12 条 R4/R9 error**。

设计使然（R4/R9 就是为了防「前缀写错导致注记静默丢失」），但它意味着
**一类内容根本用不了注记机制**：语言生态里那些注释语法与语言本身不同的配置文件。
本轮的处理是把标记换成普通注释文字，信息没丢，只是不再进注记抽取与搜索索引。
**将来若有第二门语言撞上同样情况**，再考虑给 `meta.comment` 加备用前缀（要补 ADR）。
