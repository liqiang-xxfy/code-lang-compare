## 第 1 章 · 迁移的形状

为什么不能一步到位、又为什么必须有一个原子时刻：

```
增量期(可构建)  →  原子切换(唯一破坏性时刻)  →  内容爬坡(每批可构建)  →  收尾
```

- 增量期之所以可构建：旧 loader 只扫 `content/topics/` 与 `languages/<id>/snippets/`，新增的
  `catalog/`、`languages/<id>/<section>/`、`pairs/` 对它**不可见**，旧管线原样跑绿。
- 原子时刻之所以不可拆：`RenderedSnippet` / `RenderedChapter` 的形状变了，而 `repository.ts` 的
  `import.meta.glob` 立即按新形状消费；`analyzeContent()` 又是 validate / build / tests 的共用入口。
  任何一步单独落地，项目既读不了新内容也读不了旧产物。
- **主干策略下的含义**：虽然是分步提交，但「规则 + 构建产物 + 运行时」三步必须落在**同一个提交**里。
  此处会有一段时间构建红，已接受。

## 第 3 章 · 各阶段详解

每阶段四段式：**做什么 / 改哪些文件 / 验收信号 / 坑**。

### S1 · 数据契约

- **做什么**：在 `src/schemas/index.ts` **只追加** v2 的 schema 与构建产物接口。
- **改哪些文件**：`src/schemas/index.ts`（唯一）。追加 `catalogSchema`、`boxSchema`、语言内容文件
  schema；`pairs/` 复用旧 schema。
- **最关键的一处**：构建产物契约必须一次定死「第 ③ 槽两种角色」——构建期要预渲染出
  `baselineHtml` 与 `vsHtml` 的**映射**（构建期不知道用户的基准，运行期要按当前基准取用）。
- **坑**：新增到 `src/` 的代码会被两个 verify 脚本扫描——`verify:ext` 的第二条断言**不剥注释**地
  找**带引号**的语言 id，`verify:sections` 找带引号的板块 id。schema 的注释与 message 一律用
  `<section>/<chapter>/<feature>` 这类占位式措辞。

### S2 · catalog 清单

- **做什么**：写 `content/catalog/<板块>.yaml` + `languages/_template/` 脚手架。**纯设计，不写正文。**
- **改哪些文件**：`content/catalog/*.yaml`、`content/languages/_template/**`。
- **完成信号**：**feature 总数一旦列出来，「架构能否成立」就有答案了。**
- 试点范围：只声明 `basics/variables` 一章、5 个 feature。

### S3 · 新装载器

- **做什么**：在 `scripts/lib/core.ts` **只新增函数与常量**，不动旧函数。
- **改哪些文件**：`scripts/lib/core.ts`；新增 `tests/unit/catalog-loader.test.ts`。
- 新增 `loadCatalog` / `loadLanguageContent` / `loadPairListsV2` 与 `CATALOG_DIR` / `PAIRS_DIR` 常量。
  注意继续跳过 `_` 前缀私有目录。

### S4 · 规则集 R20–R26

- **做什么**：在 `scripts/lib/analyze.ts` 新增 `analyzeContentV2()` 实现 R20–R26。
- **R25（说明的基准归属）直接复用 `scripts/lib/lang-mention.ts` 的 `detectForeignLanguageMentions`，
  不要重写。**
- R22 / R23 迁移期用 **warn**（沿用 R18/R19 的过渡期策略：补完前把构建变红，会把
  「还没写完」和「写错了」混成同一信号）。

### S5 · 构建产物

- **做什么**：重写 `renderSnippet`、章节分片键，以及 `manifest` 的 `topics` / `pairs` /
  `sections` / `featureIndex` / `routes` / `seo`。
- **改哪些文件**：`scripts/pipeline/04-build.ts` 等。

### S6 · 运行时

- **做什么**：改 `src/content/repository.ts` / 路由 / `src/stores/` / 视图 / `CodeBlock.vue`。
- 同步点见第 4 章。

## 第 4 章 · 必须成对修改的同步点

「改 A 不改 B 会静默失败」的位置：

| 同步点 | A | B | 漏改后果 |
| --- | --- | --- | --- |
| 双角色取值 | `src/schemas/index.ts`（契约） | `04-build.ts` 的 `renderSnippet` / `CodeBlock.vue` / `MatrixLayout.vue` / `SideBySideLayout.vue` | 基准列显示成对比说明 |
| 基准 / 对比约束 | `analyze.ts` 的 R8 | `scripts/build/generate-registry.ts` 的自检 | 校验放行但构建 throw |
| `scopeOfTopic` | `analyze.ts` 的 `scopeOfTopic` | `04-build.ts` 的 `scopeOfTopic` | SEO / 覆盖率口径漂移 |
| topic 反查 | `repository.ts` 的 `topicIdOf` | `guards.ts` / `ChapterCompareView` / `SideNav` / `finalize-dist` 的 `pickPair` | 路由点不进 / 404 |
| 分片键 | `04-build.ts` 的 emit 路径 | `repository.ts` 的 `shardKeyOf` / `stores/content.ts` | **整页空白（不报错）** |
| 搜索 baseline 语义 | `scripts/pipeline/search-index.ts` | `src/content/search.ts` 的 `queryOptions` / `SearchView.vue` | 搜不到或跨基准串结果 |
| 全局 feature id | `src/schemas/index.ts` 的格式定义 | `manifest.featureIndex` / 搜索 url / 锚点 / 详情页路由 | 四处各拼一套 id → 404 或锚点错位 |
| 板块字面量 | 新代码里的字符串 | `verify:ext` / `verify:sections` | 两个闸门红，且报错指向错误结论 |

| `docs/项目架构设计.md` | 第 2 章（内容模型）与第 5 章（运行时架构）由 `对比内容架构.md` 取代，加指针 | 其余章节（管线 / SEO / 环境）不依赖内容怎么组织 |
| `README.md` | 改写「四条核心设计」 | 第 0 条讲的就是旧的「按方向组织」 |
| `CLAUDE.md` | 改写架构要点 | 同上 |
| 旧 ADR | 保留，新增 ADR-40~50 | 决策记录是历史，不删 |
| `content/` | **归档为 `content.legacy/`** | 填新内容时还能对照旧写法 |

两个要点：

- **`content/` 归档不能整目录 `mv`**：`registry.yaml`、`i18n/`、`languages/*/meta.yaml` 是 v2 仍需要的配置。
  做法是整目录 `git mv content content.legacy`，新建 `content/`，再从那三类文件复制过来改造。
- **`docs/对比内容架构.md` 里的 `content.legacy/` 目录约定**：以 `_` 开头的私有目录约定保留，用于
  `languages/_template/`。

## 第 7 章 · 风险与回退

三个代价最大的点，各自给缓解手段：

| 风险 | 缓解 |
| --- | --- |
| **catalog 粒度定错**（feature 太粗→信息量不足；太细→成本爆炸） | S2 只做一章试点，先看工作量再铺开；粒度可在铺开前免费调 |
| **双角色契约设计错**（`baselineHtml` / `vsHtml` 形状没定死） | S1 就把形状写进契约；S5 若再改，repository / 视图 / `finalize-dist` 会一起返工 |
| **R22 / R23 分级未定就开写** | 迁移期一律 warn，内容稳定后按板块收紧成 error |

**回退策略**：归档不删 → `git revert` 可整体退回；`src/generated/` 全部可再生。
